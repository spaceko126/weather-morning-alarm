# 설계 결정

각 결정은 코드와 코드 주석으로 확인한 것입니다.

## 1. 알람 직전이 아니라 미리 확인하고 판정을 저장

- **문제**: 알람 시각에 네트워크가 없거나 느리면 날씨를 확인하지 못해 울림 여부를 정할 수 없습니다.
- **결정**: 알람 60분 전과 20분 전에 사전 확인을 예약하고, 판정을 저장해 둡니다. 알람 시각에는 저장된 판정만 읽습니다.
- **근거**: `AndroidAlarmScheduler` (`PRECHECK_MINUTES = 20`, `PRECHECK_BACKUP_MINUTES = 60`), `AlarmReceiver`
- **한계**: 판정 이후 예보가 바뀌면 반영되지 않습니다.

## 2. 오래된 판정은 믿지 않음

- **결정**: 저장된 판정이 6시간보다 오래됐으면 이전 알람의 것으로 보고, '실패 시 동작'을 적용합니다.
- **근거**: `AlarmReceiver.MAX_DECISION_AGE`

## 3. 실패해도 판정을 먼저 저장하고 재시도

- **결정**: 모든 예보 제공자가 실패해도 '실패 시 동작' 판정을 먼저 저장하고 재시도합니다. 나중 시도가 성공하면 실제 날씨 판정으로 덮어씁니다.
- **이유**: 재시도가 끝나기 전에 알람 시각이 와도 저장된 판정이 남아 있게 하기 위해서입니다.
- **근거**: `WeatherCheckWorker.doWork`

## 4. 테스트용 고정 예보는 디버그 빌드에서만

- **결정**: 항상 '맑음'을 돌려주는 테스트 제공자는 릴리스 빌드에서 쓰지 않습니다.
- **이유**: 릴리스에서 모든 제공자가 실패했을 때 고정값이 성공처럼 쓰이면 '실패 시 동작'이 적용되지 않습니다.
- **근거**: `WeatherRepositoryResolver` (`stubFallbackEnabled = BuildConfig.DEBUG`)

## 5. 울림은 포그라운드 서비스로

- **결정**: 소리·진동을 포그라운드 서비스에서 냅니다.
- **이유**: 전체 화면 알람 화면이 뜨지 못하는 상황에서도 계속 울리게 하기 위해서입니다.
- **근거**: `AlarmService` 클래스 주석

## 6. 프록시 서버를 둠

- **결정**: 앱이 예보를 프록시를 통해 받고, 프록시가 Open-Meteo 와 기상청을 차례로 시도합니다. 프록시가 실패하면 앱이 Open-Meteo 를 직접 호출합니다.
- **이유**: 기상청 키를 앱에 넣지 않고, 같은 지역·시각 요청을 캐시로 묶고, 요청 제한을 걸기 위해서입니다.
- **근거**: `backend/weather-proxy/src/index.js`, `WeatherRepositoryResolver`
- **개인정보**: 캐시 키는 좌표를 소수점 둘째 자리로 묶고, 로그에는 좌표를 남기지 않습니다 (`weather.js` `roundBucket`, `index.js` `logInfo`).

## 7. 디버그 전용 기능은 디버그 소스셋에

- **결정**: 알람·스누즈를 시험하는 리시버는 `app/src/debug` 에만 둡니다.
- **근거**: `app/src/debug/.../DebugAlarmTestReceiver.kt`
